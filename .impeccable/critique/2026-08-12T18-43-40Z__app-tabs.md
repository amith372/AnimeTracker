# Design Specificity Verdict

**Split cleanly along a seam: the product's *language* is authored, its *composition* is mostly default.**

**LLM assessment.** Series Detail (mobile) is the one screen with real authorship — gradient bleeding behind the status bar with `paddingTop: insets.top` on the button row only, 30px corners breaking the radius scale deliberately, `WONT_WATCH` entries struck through rather than hidden. Library is half-authored: the status vocabulary is real, the composition is a list and a grid. **Discover and Recommendations are category-interchangeable** — swap the strings and they ship as a book tracker. `WebRecCard` is a Paper `Card` with `elevation:0, shadowOpacity:0, backgroundColor:'transparent'`, which is what "default components in a box" looks like in code.

The sharpest miss: the product's one distinctive idea — **a series is a rollup of two independent backlogs** — is expressed nowhere visually. `seasonProgress` returns real numbers, `GradientProgressBar` already exists in the repo (used only by import), and the Library renders status as an 8px dot plus 12.5px grey text. On a watch-status tracker, status is the payload; here it's the footnote.

**Deterministic scan.** 3 findings, one rule (`design-system-color`), all the same literal: `#D3E3F3` hand-typed in `series/preview.tsx:253`, `series/[id].tsx:381`, `web/DetailHeroCard.tsx:84`. `design-system-font`, `design-system-radius`, and `design-system-font-size` ran clean — fonts and type scale are genuinely disciplined. `npx tsc --noEmit` exits 0.

Two caveats: ~50 of the detector's ~60 rules are browser-scope and never ran (no served build), so "3 findings" means the static set found little, not that the suite passed. And **the detector missed the worse offender** — `#BFE0FF` at `DetailHeroCard.tsx:82` fell inside its color-distance tolerance. B flagged that as a detector miss; A independently found the same line as a P1 architectural break. Two isolated agents landing on one hex is the strongest signal in this run.

**No visual overlays.** Browser visualization was skipped — RN/Expo target with no running web server, no automation exposed. Every finding below is source-anchored.

**Where the detector was right to stay quiet:** three near-identical greys, the hard 900px breakpoint, the no-shadow depth system, and the once-only brand gradient are all committed decisions in DESIGN.md, not drift.

# Overall Impression

The domain thinking here is better than the interface expressing it. Someone made real decisions — `"doesn't count toward X/Y"` on a movie subtitle, three separate gesture targets instead of one cycling control, dropping empty halves from the status label — and every one was made against an observed failure. Then that care stops at the screen boundary. Discover and Recommendations got assembled rather than designed, and the wide-web layer, which is the newest work, is where the design system is most frequently violated.

**The single biggest opportunity:** the Library's status indicator. A two-track progress mark showing seasons and movies as separate runs would make the positioning claim visible in a glance and would be unmistakably this app.

# What's Working

1. **The status vocabulary is a genuine product asset, and the UI trusts it.** `statusLabel` drops empty halves so a film reads "Watched 0/1 movies"; `kindLabel` numbers entries "Season 2"/"Movie 1" because a truncated title couldn't distinguish them. These compound into a screen that teaches a non-obvious model without a help page.
2. **The mobile Series Detail composition.** Insets handled precisely, a deliberate scale-breaking radius for a media moment, skipped entries kept visible. It reads as designed, not assembled.
3. **The three-gesture entry row resists the obvious wrong answer** — and carries the only `accessibilityRole` in the entire codebase (`SquareCheckbox.tsx:20`).

# Priority Issues

### [P0] A failed library read is indistinguishable from an empty library
`app/(tabs)/index.tsx:59` destructures `{ series, isLoading }` and discards the `error` field `useLibrary` returns. On any network failure: `data` undefined → `series` is `[]` → the screen renders **"Nothing here yet"** to a user with 200 series. Same root cause makes Series Detail render **"Not found"** (with no back button) and Catch-up render **"you're all caught up!"**

**Why it matters:** there's no offline mode by design, so this is the most frequent failure the app will ever have — and it tells the user their library is gone. PRODUCT.md defines success as the user trusting the app enough to stop checking MAL. One false "Nothing here yet" ends that permanently.

**Fix:** read `error` and reuse the retry pattern this codebase *already has* in `discover.tsx:187-198`. Give `useSeries` an error channel instead of collapsing to `null`.
**Suggested command:** `/impeccable harden`

### [P0] The app's primary action is a 24×24pt touch target
`SquareCheckbox` is a hardcoded 24×24 `Pressable` with no `hitSlop` (`src/components/SquareCheckbox.tsx:23`). Material 3 wants 48dp, HIG wants 44pt. Worse, the surrounding 60px row is itself pressable and opens the *image dialog* — so a near-miss doesn't do nothing, it opens a modal. On reconcile, users pay this cost hundreds of times.

**Fix:** `hitSlop={{top:12,bottom:12,left:12,right:12}}` inside the component so every call site inherits it, keeping the 24px visual.
**Suggested command:** `/impeccable adapt`

### [P1] Wide-web Series Detail breaks the status system on the one screen about status
`DetailHeroCard.tsx:82` is `backgroundColor: '#BFE0FF'` — `statusDotColor` is never imported into that file. All six statuses render an identical pale blue dot, close enough to Sky Blue (`#4FA3F7`, WATCHED_PARTIAL) to actively mislead. This breaks the One Status One Color Rule and the Status Dot signature component simultaneously. **Both assessments found this independently.** Related: the new-season badge is `colors.primary` on wide web but `amberTint` on mobile — one signal, two hues.

**Fix:** add a `statusColor` prop, pass `statusDotColor(series.status.kind)`, delete the literal. Tokenize `#D3E3F3` as `heroGenresText` while you're in there — DESIGN.md already flagged its sibling `#4778AC` and that one got promoted.
**Suggested command:** `/impeccable polish`

### [P1] Wide-web Series Detail has no navigation at all
`WebSidebar` renders only inside `TabsLayout`, but `series/[id]` is a `Stack.Screen` sibling of `(tabs)` at the root. Opening any series destroys the entire desktop chrome, leaving a 13.5px text link. DESIGN.md commits to a fixed sidebar "beside the routed content" — a desktop layout whose nav vanishes on the detail view isn't one.

**Fix:** move `series/*` inside `(tabs)` with `href: null`, or lift `WebSidebar` into the root layout gated on `useIsWideWeb()`.
**Suggested command:** `/impeccable adapt`

### [P1] The destructive import says "Confirm & save"
`reconcile.tsx:167` → `replaceAllSeries` → the `replace_library` RPC, which wipes the whole library. Nothing on screen says anything is being deleted. Harmless on first import; for anyone re-running onboarding it's unannounced destruction of won't-watch marks, manual overrides, and liked flags — **none of which come from MAL and none of which the import can restore.** This has *less* confirmation than the push to MAL, which is reversible on MAL's own site.

**Fix:** when the library is non-empty, gate behind a dialog modeled on `pushConfirmDialog`, and relabel to "Replace my library".
**Suggested command:** `/impeccable harden`

### [P2] The highest-stakes result self-destructs in 4 seconds
`"Updated 43 on MyAnimeList, 7 failed"` in a 4000ms Snackbar. The app's only external write, and the user is left unable to reconcile their own MAL list. Return the failed targets; render in a dismissible dialog with "Retry failed".
**Suggested command:** `/impeccable clarify`

# Persona Red Flags

**Alex (power user):** No pull-to-refresh anywhere — zero `RefreshControl` repo-wide; the gesture every RN user reaches for first does nothing. Marking a finished 12-season show is 12 separate 24px taps, while reconcile *has* "Select all". Library has 200+ items and no sort; Recommend, with fewer, has a sort dialog. On web, nothing lives in the URL — a reload wipes filter, search, tab, genres, sort.

**Sam (screen reader + keyboard):** `accessibilityRole` appears exactly once in the codebase. Unannounced: every status filter row, grid card, kebab row, "View All", entry row, sidebar nav row. Selection state is background-color-only with no `accessibilityState` — and `WebFilterRow` applies the *identical* style for `active || hovered`, so a sighted mouse user can't tell the selected filter from the hovered one either. `textFaint` on `background` is **≈2.5:1**, failing AA and even the 3:1 large-text floor, carrying every entry subtitle and filter count; the AIRING badge is 9.5px. No dark mode at all — `MD3LightTheme` only, `StatusBar style="dark"` hardcoded. DESIGN.md's dot-plus-label pairing claim is true in 4 of 5 places and false in the one that matters.

**Casey (mobile, one-handed):** Every control sits in the top ~25%; the only thumb-reachable UI is the tab bar. The 7-chip filter row scrolls horizontally, so options 5–7 are off-screen at decision time. Optimistic writes have no in-flight state — tap, see it tick, pocket the phone, and it silently reverts behind a toast nobody saw. Android back exits the tab instead of leaving Discover's search.

**The MAL-history importer (project-specific persona):** meets the product at its least-designed screen. A flat 200-series `FlatList` with no search, filter, collapse, or progress. The one bulk tool is all-or-nothing — but CLAUDE.md records that these users historically marked only season 1 of shows they finished, meaning the work is **per-series**, exactly the granularity not offered. Then it commits destructively without saying so. The payoff for importing years of history is a title-ordered list with no way to ask "what next" — that answer is one tab away, behind a segmented button.

# Minor Observations

- `LibraryTabIcon` is a list glyph for a screen that's a poster grid on web.
- `ForYouTabIcon` rotates a square 45° with no size compensation — the bounding box grows by √2, so it optically overflows relative to its siblings.
- `WebSidebar`'s nav dot is `borderRadius: 2` on 7px — a rounded square, while every status dot in the system is a circle.
- Off-scale radii against the Scale-First Rule: `14`, `18`, `radii.md - 1`, `6`. The scale is 8/12/16/22/999.
- `rgba(59,110,165,0.08)` is retyped literally at `recommend.tsx:598` where `colors.coverPlaceholder` is byte-identical; `0.12`/`0.18` siblings are untokenized.
- Snackbar durations disagree for comparable weight: 4000 for a MAL push result, 6000 for a save error.
- Searchbar styling is duplicated across three files with different values, including a hand-typed `borderRadius: 999` where `radii.pill` exists.
- Fixed heights against scaling text (`minHeight: 42`, `34`, `width: 158`) with `allowFontScaling` never disabled — Dynamic Type will clip.

# Questions to Consider

1. **If a series is genuinely two backlogs, why is that only ever a sentence?** `GradientProgressBar` already exists. What stops a two-track progress mark from becoming the Library's signature instead of an 8px dot?
2. **What if "Auto" weren't a fifth chip?** It's categorically different — "clear my override" — yet it's the same shape and size as four statuses, pushing a 4-option decision to 5 and making the model opaque.
3. **Why doesn't the Library answer "what do I watch next"?** It's already computed, costs zero API calls, and lives behind a segmented button on another tab.
4. **What if the 200-series reconcile were treated as the product's first impression rather than a setup step?** Grouped by MAL status so `completed` shows are pre-confirmed? Progressive, so the library exists after 20 shows?
5. **Warm Amber already means three things** — Currently watching, the rating badge, and the new-season tint — while the One Status One Color Rule is declared inviolable. Is the rule wrong, or are the badge and alert wearing a color they shouldn't?
